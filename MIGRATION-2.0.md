# Ruby SDK 2.0 migration

Version 2.0 changes capture and hook timing. Keep a pinned 1.x gem available during rollout.

Exception capture uses Ruby's built-in stored type, message, backtrace, and cause accessors instead of calling application overrides. Custom dynamic `class`, type-name, `message`, `backtrace`, or `cause` methods no longer contribute telemetry. Stack and cause chains have finite limits; application exceptions and logging behavior remain unchanged.

Accepted `capture_log` and `capture_message` calls no longer invoke `to_s` on arbitrary application objects. Strings and simple scalar values remain readable; other objects become `[unsupported log message]`. Format custom objects in application code before passing them to the SDK if their text is required, keeping that application work outside the SDK's capture guarantee.

Context keys must be strings, symbols, or bounded integers. Other key types are skipped. Unsupported context values become `[unsupported value]` instead of invoking application `to_s`, `to_h`, or `to_hash` methods. `capture_request` accepts Hash request/response metadata; custom objects with conversion methods are no longer expanded automatically. Convert such objects to a plain Hash in application code before calling the SDK if their fields are needed. This keeps application conversion work outside the SDK's capture guarantee.

Capture now checks the effective local and remote log policy before constructing a log event or invoking `before_send`. Hooks do not observe filtered logs. `capture_logs: off` rejects every severity, including FATAL. A connected client begins with a restrictive policy until its initial remote configuration is fetched on a separate bounded config poller; early low-severity records may therefore be omitted. A stalled fetch cannot hold the event sender.

`before_send` runs on the owned sender thread rather than the application caller. A callback must not rely on request-thread locals or mutable request objects that are not in the event envelope. It still receives a protected event and can return a valid replacement or `nil`. Automatic batch and interval delivery now happen without an explicit `flush`. Explicit `flush` waits up to five seconds for the sender and returns `false` on timeout, rejection, or transport failure. Applications needing shutdown delivery should call it during their controlled shutdown window.

Automatic `at_exit` and unhandled-thread exception hooks enqueue the exception and wake the sender without waiting. A process that exits immediately may lose that best-effort event; use an explicit controlled `flush` where delivery is required. After a process fork, the child drops the parent's queued events, request context, probes, and sender state, then starts its own sender on first SDK use. The effective capture restrictions remain in force until the child refreshes remote configuration. Re-establish child-specific context after forking.

Queued and in-flight events, including retained hook replacements, share a 1,000-event/8 MiB ownership budget. A held transport batch remains reserved and cannot be displaced; priority eviction applies only to unsent work. When full, lower-priority logs and ordinary requests are discarded before exceptions and failed requests. Even an all-ERROR or all-exception burst has a finite cap; excess records return before application message inspection and appear in a bounded pressure aggregate after room returns. Suppressed counts are reported as bounded `error_suppressed` aggregates with `reason: queue_pressure` and a `level` class. Transport retries still preserve the usual acknowledgement semantics within that budget. This is best-effort telemetry: an overloaded or unavailable transport can lose events to protect host throughput.
